Give your AI agent your design system.

design-md-mcp reads any DESIGN.md and answers your agent in a few lines: the exact token, the component class to reuse, the rule not to break. On-system UI, without pasting the whole spec into every prompt.

$claude mcp add tidepool -- npx -y github:tingowiggle/design-md-mcp --example tidepool

Install

Set up in a minute.

Needs Node 18+. Works with any MCP client: Claude Code, Cursor, Windsurf, Claude Desktop, VS Code and more.

1
Copy the Tidepool files into your project You get DESIGN.md, tokens.css, icons.js and tide.js in ./tidepool.
$npx -y github:tingowiggle/design-md-mcp init tidepool
2
Connect the MCP server
$claude mcp add tidepool -- npx -y github:tingowiggle/design-md-mcp --file ./tidepool/DESIGN.md
{
  "mcpServers": {
    "tidepool": {
      "command": "npx",
      "args": ["-y", "github:tingowiggle/design-md-mcp",
               "--file", "./tidepool/DESIGN.md"]
    }
  }
}
Add to your client's MCP config (e.g. .cursor/mcp.json), then restart it.
3
Ask your agent
You
"Build a proposal voting screen in the Tidepool style, light and dark. Start with get_screen_kit."
You
"Add the 3D Tide to the empty state of the activity tab."
1
Have a DESIGN.md YAML tokens between --- fences (colors, typography, rounded, spacing, components), then markdown sections with your rules. Optional extras next to it: tokens.css (CSS variables + component classes) and showcase.html (markup examples).
2
Connect the MCP server
$claude mcp add my-design -- npx -y github:tingowiggle/design-md-mcp --file ./DESIGN.md
{
  "mcpServers": {
    "my-design": {
      "command": "npx",
      "args": ["-y", "github:tingowiggle/design-md-mcp",
               "--file", "./DESIGN.md",
               "--css", "./src/styles/tokens.css"]
    }
  }
}
Options: --css stylesheet(s) · --examples HTML that uses your components · --docs extra rule files · --scope .app if tokens live on a class.
3
Ask your agent
You
"Build the settings page with our design system. Use get_screen_kit first and reuse existing classes."
You
"Run check_value on every hex and px in this file and replace them with tokens."
Tools

Seven tools your agent can call.

Your agent asks a small question and gets a short answer: a couple of lines for a colour, about a page of text to set up a whole screen. Without it, the agent reads the entire design system, about 10 pages, every time.

For developers: ~800 tokens to load the tools, 50–650 tokens per answer, vs ~6,300 for the full Tidepool files.

get_screen_kit
Start here. Setup, every reusable class, the most relevant components with markup, and the must-follow rules, in one call.
"approve payment sheet"about a page (~650 tokens)
get_component
The class to reuse, a real markup example, resolved spec values and written rules.
"bottom-sheet" → use .sheeta short paragraph (~170 tokens)
get_token
Exact value, light and dark, the CSS variable, and where to use it.
"primary" → var(--primary)2–3 lines (~80 tokens)
find_token
Plain-words search for the right token or component.
"rejected status"2–3 lines (~90 tokens)
check_value
Is this hex or px in the system? If not, the nearest tokens.
"#0F7B6D" → var(--primary)2–3 lines (~55 tokens)
get_rules
One rule section by topic: colour rules, typography, do's and don'ts.
"colour rules"a short paragraph (~120 tokens)
ds_overview
Every token and component name, no values. A cheap map of the system.
orient firsthalf a page (~420 tokens)
